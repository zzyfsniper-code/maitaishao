# 买汰烧 · 家庭厨房 Demo

本地单家庭应用。使用真实 Agent、服务端规则校验和 SQLite 保存数据。当前版本用于跑通协作与业务流程，示例菜谱及搭配规则不代表已接入正式营养标准。

## 打开

Windows 双击项目内的 `启动厨房.cmd`，然后访问 **http://127.0.0.1:4317**。再次启动会复用已运行的服务。

也可以在项目目录执行：

```powershell
npm.cmd start
```

需要 Node.js 24 或更新版本。首次安装执行 `npm.cmd ci` 与 `npx.cmd playwright install chromium`。服务只监听本机。浏览器关闭后服务仍可运行，电脑关机或服务退出后定时任务不会执行。

## 已接通的流程

- 示例家庭与 50 道示例菜谱，首次启动生成下周 21 餐。数据保存在 `data/kitchen.sqlite`，重启与刷新不会清空。
- 家庭成员档案、固定七天三餐规律、临时餐次人员和饭量；临时调整先展示建议再确认。
- 成员形象上传、替换、恢复默认；形象原始比例保留，个人卡片展示完整图片，菜单用缩略头像。支持 PNG、JPEG、WebP，上传后生成不超过 512px 的本地展示图。
- Profile 预设标签和自定义标签；控糖等目标只记录意向，等待正式规则，不自行推导营养数值。明确过敏、禁用食材和不吃辣约束参与排菜。
- 按规则生成菜单、同类菜替换、撤销；检查共享餐过敏和忌口、跨周重复间隔、已确认的幼儿园同日午晚餐重复。
- 真实 Agent 理解自然语言，返回限定操作意图。明确的对话修改校验后直接保存，并回复实际结果；只有用户说“先预览/先别保存”等才展示待确认建议。有歧义先询问，未知菜名或约束冲突会被拦截。
- 菜谱详情与文字教程、B 站菜名搜索。Agent 可从菜名、文字、链接或图片整理新菜草稿，核对后才能入库。
- 幼儿园午餐支持公开网页链接、上传截图、粘贴文字，经过真实模型识别、可编辑预览和确认。只导入午餐，保留原文/截图与日期依据。
- 按日期范围、菜单版本和份量汇总采购；兼容单位合并，不混加克/毫升/个，不计入园内午餐，不扣库存。支持文本导出。
- 保存成员反馈；长期“不再做”的建议需要显式确认；不会将一次剩饭自动写成永久饭量。
- 每周日 20:00、Asia/Shanghai 时区后台生成下周菜单，可修改。已有菜单跳过，不覆盖手动修改。失败记录可见、支持手动验证/重试。
- 禁忌、菜单池、营养搭配资料的上传保存入口，状态为待接入，不会自动改写规则。

## Agent 连接

默认使用 Pi Agent SDK 1.5.2，复用本机 `~/.pi/agent` 的模型连接与凭据。当前连接为 `fde / deepseek-flash`，Base URL 为 `https://fde.wscn.net/v1`；用户确认它与先前提供的 `deepseek-4.1-flash` 是同一个模型。

厨房页面通过自己的 Node 后端调用 Pi，不依赖 Pi Web 页面保持打开。Pi Web 控制台为 http://127.0.0.1:30141。厨房提供档案查询、经 MCP 查询菜谱知识、试排菜单、档案及表单修改预览、采购计算和文章图片读取工具，不加载编码工具、全局扩展、个人技能或其他项目上下文。Pi 工具试排结果经过后台复检；明确对话指令直接保存，用户要求先预览时才等待确认。

每次请求使用独立 Pi 内存会话；连续对话通过厨房数据库最近十条消息传入。没有宣称 Pi Web 会话与厨房自动互通。超时或失败会显示错误，不以模板冒充模型响应。

厨房设置仍可选择本机 Codex 或直接兼容 API。直接 API 的 Key 只保存在本地后台，空值保留已有 Key；Pi 直接使用其已有配置。`data`、`.env`、本机 Pi 凭据不提交到 GitHub。图片识别要求模型支持视觉。

## 菜谱知识库与对话编辑

菜谱已迁移到 SQLite 独立知识表，通过 MCP stdio 连接厨房后台。原有 ID、内容和菜单保留，迁移前状态留存；知识更新保存逐版本历史。网页「菜谱知识库」支持手动添加、助手整理、修改已确认菜谱和查看历史。新菜仍须核对入库，模型和网页读取同一份知识。数据库与成员数据不会上传 GitHub。

对话支持修改成员标签、过敏、喜好、忌口、年龄、默认饭量、固定规律，以及排菜设置、菜谱知识、幼儿园午餐草稿和待接入资料。仅修改指定字段；标签新增/移除不会覆盖其他记录。明确指令直接执行，要求预览时才等待确认。上传图片、链接识别和本机模型凭据仍使用对应入口。

详细调用关系、MCP 工具清单及 Skill 的区别见 [Agent 与知识库架构](docs/Agent与知识库架构.md)。

## 品牌与动画

名称统一为买汰烧，使用用户最新提供的带字 App 图作为侧栏、登录页和网页图标。页面顶部为约 80px 的窄栏，整合家庭插画、头像和菜单概况。五位家庭角色头像由内置 imagegen 参照用户插画生成，档案中上传的图片优先；素材和提示词见 [形象素材说明](docs/形象素材说明.md)。

清蒸鲈鱼已接入专属 SVG 动画：洗净、铺姜葱、盖锅清蒸、出锅调味，约 6.8 秒。其他菜暂保留通用四拍示意：备菜 850ms、下锅 650ms、翻炒 1350ms、出锅 1100ms。首次打开自动播放，可重播；关闭弹窗取消动画，减少动态效果时显示成品。动画不代表真实烹饪用时，实际做法以下方菜谱为准。

组员新版蒸鱼动画的场景字幕、步骤参考分钟和爸爸/妈妈切换已接入。人物改为无锅具的透明形象，与画面中的同一口蒸锅配合；参考分钟为 3 / 1 / 8 / 3，合计约 15 分钟。素材、提示词和接入源码见 [蒸鱼动画人物与接入说明](docs/蒸鱼动画人物与接入说明.md)。

加载页复用通用炒菜动画：等待配置或家庭数据时循环播放，数据就绪自动进入；首次输入口令后等待数据也会显示。失败时显示错误与重新加载入口，不设置额外等待时间。

## 组员在线访问

GitHub 仓库：https://github.com/zzyfsniper-code/maitaishao

页面：https://zzyfsniper-code.github.io/maitaishao/

前端由 GitHub Pages 托管；Pi 和 SQLite 仍运行在主厨电脑，通过带口令的本地共享网关及 Cloudflare Quick Tunnel 连接。组员需要口令，模型 Key 不发送到浏览器。共享网关不允许远程修改模型连接配置。四位组员共用同一份数据，版本检查防止过期建议覆盖新修改；当前没有分别识别每位组员的账号系统。

电脑、厨房服务、共享网关和隧道都需保持运行。Quick Tunnel 地址在重建后会变化，需要更新前端的连接地址并重新发布；发布完成仍需等待 Pages 构建。它适合当前培训演示，没有长期在线保证。

重启步骤：在项目目录的三个终端分别运行 `npm.cmd start`、`node server/share-server.mjs`、`.\.tools\cloudflared.exe tunnel --url http://127.0.0.1:4319 --no-autoupdate`。将隧道输出的新 HTTPS 地址填入 `data/share-config.json` 的 `apiBase` 字段，保存为 UTF-8，然后执行下方发布命令。终端保持打开；已有服务运行时不要重复启动。当前机器的自动启动脚本未通过文件保留检查，因此本版本仅提供这些手动步骤。

本机口令和隧道地址保存在被忽略的 `data/share-config.json`。分享网关监听 127.0.0.1:4319，主应用监听 127.0.0.1:4317；只把共享网关接入隧道。口令仅保存于组员浏览器当前会话。错误口令连续十次会暂时限制该来源五分钟。

发布：`node scripts/build-pages.mjs` → `python scripts/github-pages.py publish`。脚本只把 `site/` 前端上传到 gh-pages 分支，并保留旧提交；主源码位于 main。GitHub 凭据来自环境变量或本机 Git 凭据管理器，不写进项目。停止在线分享时，核实并停止 `data/tunnel.pid` 对应的本项目 cloudflared 进程；本地厨房不受影响。

## 规则状态

执行版本 `demo-v1`：早餐主食和蛋白质，午晚餐荤素搭配；同菜中间至少隔三个完整自然日，按稳定菜谱 ID 检查跨周历史；基础早餐例外仅限相应标记菜谱在早餐之间重复。幼儿园仅检查同日午餐与家庭晚餐，尚未扩大成跨日规则。

示例菜谱用量为主材生重/包装量估算，调味料另备。采购小数“个”是理论用量，购买时自行向上取整。营养精确比例、医学限制、完整食材同义词库及正式菜单池待用户文档确认。负面规则已整理为项目接入规范；正向多样性排序和缺数据不评价已接入。精确营养参考、成分表与交换份仍待核实。

详细规则见 [负面规则](docs/负面规则.md)、[正向规则](docs/正向规则.md) 与 `rules/` 中的 JSON。负面规范的新增能力尚未全部启用；新菜单记录正向版本 `positive-v1`，已有菜单保留。

## 验证

```powershell
npm.cmd test
python tests/browser_smoke.py
```

浏览器验收使用已安装的 Python Playwright 与 Chromium，自动启动 4318 端口和临时数据库，不改用户 Demo 数据。

需要运行真实模型验收时：

```powershell
$env:KITCHEN_LIVE_AGENT = '1'
python tests/browser_smoke.py
```

该选项会产生真实模型调用。测试截图与结果写到 `tests/artifacts/`，不纳入 Git。正常业务测试覆盖菜单、跨周间隔、过敏、份量、采购、过期建议、持久化；浏览器覆盖成员形象与标签、临时安排、菜单替换撤销、采购导出、规则资料与响应式页面。

## 文件归属与接手

| 文件 | 作用 | 对应负责人 |
| --- | --- | --- |
| `server/index.mjs` | HTTP 路由、操作编排、定时任务、版本检查 | A，公共入口变更统一合并 |
| `server/store.mjs` | SQLite 状态持久化与并发更新保护 | A |
| `server/agent.mjs` | 模型适配器、结构化响应、连接配置 | A |
| `server/source.mjs` | 公开链接读取、超时与错误处理 | A，供 B/D 使用 |
| `server/domain.mjs` | 家庭上下文、菜单生成、规则校验、采购计算 | B/C/D 按函数边界，A 协调公共修改 |
| `server/seed.mjs` | 示例家庭、菜谱、初始规则 | B/D |
| `public/app.js` | 页面、表单、对话、确认与失败状态 | 按模块由各负责人接手，A 合并 |
| `public/style.css`、`profile.css`、`readability.css` | 公共设计与响应式布局 | A |
| `docs/API.md` | 接口与协作约定 | 全员遵守 |

这是可运行的轻量 Demo，共享入口暂集中。并行接手时每人独立分支/工作目录，由 A 协调公共文件，后续可沿业务边界拆页，不要各自产生一套成员或菜谱 ID。
