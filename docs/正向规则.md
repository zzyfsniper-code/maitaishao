# 买汰烧正向搭配规则

版本 positive-v1，2026 年 11 月 15 日。依据组员《营养规则与食谱含量》v1.0，适配当前七天三餐、实际出席成员、菜谱参考份数及 Pi 助手。

本版已接入食材多样性排序与缺数据不评价。原有早餐主食加蛋白质、午晚餐荤素搭配继续使用；新增规则只影响后续生成和调整候选。已有菜单保留原样，新保存的菜单记录 positiveRuleVersion。精确营养核算及等热量换菜尚未启用。

## 已融合到排菜的规则

| 编号 | 行为 | 实现位置 |
| --- | --- | --- |
| P01 | 先通过过敏、明确忌口、园所午餐和重复间隔检查，再参与正向排序。多样性不能抵消硬限制 | domain.mjs 的 eligible 与 validateMeals |
| P02 | 早餐保留主食和蛋白质类别；午晚餐保留荤菜、蔬菜与主食的现有搭配。用户指定道数时保留限制范围和搭配未完全满足的提示 | buildMeals |
| P03 | 对每位当餐出席成员，优先安排其本周家庭菜单尚未出现的食材；不同家庭成员各算各的，不把爸爸吃过当成宝宝吃过 | nutrition.mjs 的 diversityBonus |
| P04 | 同一食材重复出现只计一次；已支持的同义名归一；油、盐、糖及列入字典的调味料不计入食材种类 | foodNames |
| P05 | 页面显示已记录家庭食材种类数，明确范围仅为已安排的家庭餐次，不能称为已吃够或全天达标 | nutritionSummary 与本周菜单页 |
| P06 | 缺成分表、油盐用量、人群参考或实际摄入数据时，营养状态为 unavailable，页面写“暂不评价”；没有数据不填 0，不显示不达标或完成率 | nutritionSummary 与 Pi 查询上下文 |
| P07 | 按现有每位成员参考份数生成家庭总量；园所午餐只用于避重，不加入家庭采购 | contextFor 与 shopping |

P03 的内部产品权重为：候选每新增一种已记录非调味食材贡献 1 分，再按当餐成员人数取平均，叠加现有口味及重复使用排序。这是让同等可行菜谱更丰富的产品参数，不是营养评分，不向用户展示分值，也不承诺一定达到每日或每周目标。新增食材必须已经存在于确认菜谱，不能为加分虚构配料。

种类统计使用当前菜谱数据。字典尚不能覆盖所有复合食品和别名，显示的是“已记录食材种类”，不假称权威食物分类或完整摄入评估。宝宝工作日午餐在园所，园所记录没有实际摄入克数，因此不得用家庭早餐加晚餐判断宝宝全天营养。

## 定量规则的接入合同

| 项目 | 必须具备的输入 | 计算与表达 |
| --- | --- | --- |
| 个体参考值 | 实际年龄、性别、必要的生理状态与活动水平；参考表逐项来源、版本、单位、口径和核实状态 | 按营养素自己的年龄分段匹配，不按“6 至 10 岁”等产品标签直接套一行 |
| 食材营养 | 标准食材 ID、可食部生重、每 100g 成分、来源与缺失字段 | 已知项可以标估算；未知项保留 missing，不当作 0 |
| 生熟换算 | 原料状态、食材及做法对应的出成率、损耗与可食部依据 | 不能给所有米面、肉菜套统一系数；展示熟重须注明换算，避免再次乘出成率 |
| 调味料 | 油盐及复合调料逐项用量、适用成分信息 | 没有油盐记录时，不能把低盐低脂判断算作完成 |
| 评价口径 | EAR、RNI、AI、UL、GUIDE 等明确类型 | 类型不混用；低于 RNI 不能直接诊断缺乏，指南建议上限不改写为 UL |
| 三档文案 | 经确认的 expression.json、每个营养素对应阈值、比较运算符和可信度规则 | 仅在依据完整时使用定性表达，不公开营养分数或完成百分比；pending 一律不评价 |
| 周统计 | 按人、按日、含在外餐次的可靠摄入或完整计划，以及覆盖天数 | 原文提出蛋白质、钙、纤维看平均，上限类另报峰值日；缺失日期不补 0，周平均不提高数据可信度 |
| 等热量换菜 | 两菜完整成分、可比生重、正能量值、同交换组依据与缩放后可行份量 | 先核对禁忌，再算缩放后变化；同时报告有利和不利项，任何一菜关键成分不完整则结论不可用 |

现有 portion 与 servings 是家庭饭量参考单位，不等于文档的 90 kcal 交换份，也不等于固定克重。“同类换一道”目前保留原参考份数并复检限制，不能标成“等热量换菜”。原文的日常食用份量与交换份必须分别存储；不能建议用户为了一个交换份机械增加数百克某一种蔬菜。

## 暂不直接采用的数值和结论

1. 文档明确部分儿童蛋白质、钙以及成人钙属于 medium，尚未与原书逐项核对。本版不把它们自动设置为个体营养目标，尤其不对四岁的宝宝套用成人份量或能量处方。
2. 13 个人群的汇总来自演示成分表反算，原文注明不是个体实测摄入；也不是当前家庭 50 道菜的营养实测。页面不把这些结果复制到本家庭。
3. “白米饭 100g 为 346 kcal”的示例名称与生米口径容易混淆。正式食材必须明确 raw 或 cooked，以及可食部基准，不直接以显示菜名判断计算单位。
4. 文中既使用“食盐小于 5g”，又出现“约 5g 适宜”；还把烹调盐与总钠折盐列在同一表里。须先明确比较边界、舍入方式与总膳食钠范围，不照表输出通过结论。
5. 文档列出 high 与 medium 的部分充足阈值，但没有完整 expression.json，中间档、上限档的所有边界无法复现；不会只凭两条百分比补造整张分档表。
6. 文中的人群表与后文 DRIs 年龄分段不一致；活动水平又影响能量，不能简化为三个静态标签。缺生理状态或活动信息时不悄悄默认健康、非孕或轻体力。
7. 原文“储备型”只作为其周统计分组命名，不转述成身体能无限储存蛋白质等生理结论。维生素 D、铁、能量在当前无完整依据时不评价，也不将文档的解释扩展为“这些营养不重要”。

## 后续需要组员补交的数据

文档提到但本次附件中没有提供的 expression.json、标准食材成分表、参考值原始表、人群与年龄映射、含油盐的逐菜用量、出成率依据，以及 src/selftest.mjs。文档自述的 18 条断言不能替代实际代码与执行结果。

接入顺序为：核实来源与单位，映射现有菜谱及成员字段，检查成分覆盖率，复现代表食谱，验证同菜自比为零与换菜双向变化，再开启相应指标。无依据项继续显示“暂不评价”，无需阻塞现有菜单流程。

## 验收

已运行的测试覆盖：食材别名合并、排除调味料、重复菜不重复计种类；按实际成员及选定周计算多样性；没有成分数据时营养状态 unavailable；Pi 工具试排不写数据库；原有过敏、跨周间隔、确认和采购规则继续通过。具体结果见 docs/VERIFICATION.md。

后续定量验收还需覆盖：未知食材不作 0、缺失日期不补 0、按真实年龄查表、儿童不套成人目标、生熟口径只转换一次、油盐不遗漏、参考值类型不混用、pending 不评价、周统计沿用同一档位函数、盐等上限另报峰值日、两菜完整覆盖且同口径才能比较、正负变化一并显示。

## 参考依据

[中国营养学会膳食指南核心工具包](https://www.cnsoc.org/activitykit2/6522002010.html)提出食物多样的一般建议。本项目先统计所掌握的家庭菜单，不将其当作完整全天摄入达标。

[中国营养学会少盐少油准则](https://dg.cnsoc.org/article/04/ApX3_ozGTmSoqQaFFh5z_Q.html)说明盐摄入需考虑调味品及在外用餐，并区分成人儿童。它不能支持只根据家庭烹调盐判断全天总量。

[中国营养学会 DRIs 2023](https://www.cnsoc.org/drpostand/)作为后续逐项核实入口。正式数值仍需匹配具体营养素、年龄、生理条件与版本；本版未声称已完成全部原书数值复核。
